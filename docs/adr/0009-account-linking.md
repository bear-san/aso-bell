# ADR 0009: チャットアカウントと Google アカウントの連携と、WebConsole の認可根拠

- 状態: 採用
- 日付: 2026-09-11

## 文脈

要件追加: Slack / Discord のユーザーと Google アカウントを紐づけ、`/asobell login` で本人にだけ見えるメッセージ(非対応なら DM)として連携 URL を返す。また WebConsole からイベントを作成できるようにする(主催者が必要)。

従来案では WebConsole のログインを許可リスト(メール / ドメイン)で制限していたが、連携が導入されることで「Bot が導入されたワークスペースのメンバーであること」を認可根拠にできる。

## 決定

1. 連携トークン(256 bit、10 分、一度きり)を `/asobell login` で発行し、`<BASE_URL>/link/<token>` をエフェメラル(非対応なら DM)で返す。DB にはハッシュのみ保存する
2. `/link/<token>` の GET はトークンを消費せず、ページ内の明示操作(POST)で消費する。投稿時はリンクプレビューを抑止する
3. 初回の Google ログインは、有効な連携トークンを伴う場合、または任意設定の許可リストに一致する場合に限りアカウントを作成する。許可リストは必須ではない
4. WebConsole からのイベント作成の主催者は、ログインユーザーの当該ワークスペースにおける ChatIdentity とし、未連携の場合は作成を拒否する
5. 1 チャットユーザーは 1 Google アカウントにのみ紐づく(一意制約)

## 理由

- 連携 URL を受け取れるのは、そのワークスペースでコマンドを実行できる本人だけであり、これが最も自然な本人確認になる
- 主催者を連携 ID に固定することで、WebConsole から作成したイベントもチャット上で主催者としてコマンド操作できる
- GET で消費しない設計は、Slack / Discord のリンクプレビュー機能がトークンを先取りするリスク(公式には未記載だが報告あり)への備え

## 結果

- 連携 URL を第三者に渡すと第三者のアカウントに紐づく。文言で「あなた専用」と明示し、連携ページにチャット上の表示名を出して確認を促す
- 許可リストによるログインは、チャット連携なしで運用画面を見たい管理者向けの補助手段として残す
