# ADR 0003: cron ライブラリではなく MongoDB 永続ジョブキューを使う

- 状態: 採用
- 日付: 2026-09-11

## 文脈

リマインド、チラ見の 1 時間期限、自動終了、アーカイブは「未来のある時刻に 1 回実行する」処理である。候補は (a) `robfig/cron` 等のインメモリスケジューラ、(b) MongoDB にジョブを永続化しポーリングするワーカー。

## 決定

(b) を採用する。`jobs` コレクションに `runAt` / `status` / `leaseUntil` を持たせ、`FindOneAndUpdate` で原子的に claim する。

## 理由

- プロセス再起動・デプロイでスケジュールが失われない(NFR-03)
- イベント編集時の「該当ジョブのみ取り消して再生成」が DB 操作で完結する
- 複数プロセスでもリースにより二重実行しない
- `robfig/cron` は 2024-07 以降更新がなく、cron 式の定期実行という本件に不要な機能が主目的
- 追加依存がゼロ

## 結果

- ポーリング間隔(既定 10 秒)分の遅延が生じるが、リマインド用途では許容範囲
- ジョブハンドラは冪等に書く必要がある(実行前に DB 状態を再確認)
