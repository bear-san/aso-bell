# 01. 要件定義

## 1. プロダクト概要

あそベル (aso-bell) は、Slack / Discord 上で「遊びの予定」を立ち上げ、連絡用のプライベートチャンネルを作成・管理し、参加者へリマインドを届ける Bot とその管理コンソールである。

| 要素 | 内容 |
| --- | --- |
| 利用者 | Slack ワークスペース / Discord サーバーのメンバー(イベント主催者・参加者) |
| 管理者 | WebConsole に Google アカウントでログインする人(権限の区別なし) |
| 対応チャット | Slack または Discord(1 グループにつきどちらか 1 つ)。Provider を gRPC サービスとして分離し、将来の追加が可能 |
| データストア | MongoDB(Manager のみが接続する) |
| 配置 | 1 グループにつき Manager コンテナ + Provider コンテナ + MongoDB のセット。複数グループに提供する場合はセットを複数用意する |

## 2. 用語定義

| 用語 | 英語識別子 | 定義 |
| --- | --- | --- |
| Manager | Manager | イベントのライフサイクル・DB・ジョブ・HTTP API・WebConsole 配信を担うサービス。gRPC サーバーを持つ |
| Provider | Provider | 1 つのチャットツール(Slack App または Discord Bot)に接続し、Manager と gRPC で通信するサービス。資格情報は起動時の環境変数で受け取る。Manager と 1:1 で対になる |
| ワークスペース | Workspace | Slack の Team、Discord の Guild に対応する単位。Provider から通知される |
| チャット ID | ChatIdentity | Slack / Discord のユーザーと WebConsole の Google アカウントの紐づけ |
| 連携 | Link | チャットの `/asobell login` から発行される URL を開いて ChatIdentity を作ること |
| イベント | Event | ユーザーが立ち上げた遊びの予定。ライフサイクルを持つ |
| 主催者 | Organizer | イベントを立ち上げたチャットユーザー |
| イベントチャンネル | Event Channel | イベントごとに作成されるプライベートチャンネル |
| 立ち上げメッセージ | Announcement | イベント作成時にコマンドが実行されたチャンネルへ投稿され、ピン留めされるメッセージ。「参加」「チラ見」ボタンを持つ |
| 募集チャンネル | Recruit Channel | ワークスペースごとに任意で設定する、全イベントのリマインド・告知が流れるチャンネル |
| 参加 | Join | イベント参加者として恒久的にイベントチャンネルへ追加されること |
| チラ見 | Peek | 1 時間だけイベントチャンネルへ追加されること |
| 参加者 | Participant | 参加(Join)したユーザー |
| チラ見者 | Peeker | チラ見(Peek)中のユーザー |
| リマインド | Reminder | イベント前に自動投稿される通知 |
| リマインドポリシー | Reminder Policy | リマインドをいつ・どの頻度で投稿するかの設定 |
| アーカイブ | Archive | イベント終了後のチャンネル処理。Slack はチャンネルアーカイブ、Discord は `archived_` prefix へのリネーム |

## 3. 機能要件

### 3.1 チャンネル管理 (FR-CH)

| ID | 要件 |
| --- | --- |
| FR-CH-01 | ユーザーがスラッシュコマンドでイベント立ち上げを宣言すると、プライベートなイベントチャンネルが作成される |
| FR-CH-02 | 立ち上げメッセージはコマンド実行チャンネルへ投稿され、イベント終了までピン留めされる |
| FR-CH-03 | 立ち上げメッセージには「参加」ボタンがあり、押下したユーザーは参加者としてイベントチャンネルへ恒久的に追加される |
| FR-CH-04 | 立ち上げメッセージには「チラ見」ボタンがあり、押下したユーザーは 1 時間だけイベントチャンネルへ追加される。1 時間経過後に自動で除外される |
| FR-CH-05 | チラ見中に「参加」を押した場合、参加者へ昇格し、自動除外は取り消される |
| FR-CH-06 | 参加者はデータベースで管理され、リマインド等に利用される |
| FR-CH-07 | イベント終了後、イベントチャンネルはアーカイブされる。Slack: `conversations.archive`。Discord: チャンネル名に `archived_` prefix を付与 |
| FR-CH-08 | ワークスペースごとに任意で募集チャンネルを設定でき、全イベントのリマインドと立ち上げ告知が流れる |
| FR-CH-09 | 募集チャンネルはスラッシュコマンドまたは WebConsole から設定・解除できる |

### 3.2 イベント管理 (FR-EV)

| ID | 要件 |
| --- | --- |
| FR-EV-01 | イベントは `open`(募集中) → `ended`(終了) または `canceled`(中止) のライフサイクルを持つ |
| FR-EV-02 | 「参加」ボタン押下時、イベントチャンネルへ参加メッセージが投稿される |
| FR-EV-03 | 「チラ見」ボタン押下時、イベントチャンネルへチラ見メッセージが投稿される(参加メッセージと区別できる文言) |
| FR-EV-04 | リマインドはイベントチャンネルと募集チャンネル(設定時)の両方へ投稿される |
| FR-EV-05 | リマインドの投稿ペースは、主催者がスラッシュコマンドまたは WebConsole で設定できる |
| FR-EV-06 | イベントは主催者のコマンド、WebConsole 操作、または終了予定時刻の経過により終了する |
| FR-EV-07 | イベントは主催者のコマンドまたは WebConsole 操作により中止できる。中止時もチャンネルはアーカイブされる |
| FR-EV-08 | イベントのタイトル・日時・説明・リマインドポリシーは開催前に編集できる |

### 3.3 アカウント連携 (FR-LK)

| ID | 要件 |
| --- | --- |
| FR-LK-01 | チャットで `/asobell login` を実行すると、本人にだけ見えるメッセージ(エフェメラル)で連携用 URL が返る。エフェメラルに対応しない Provider ではダイレクトメッセージで返す |
| FR-LK-02 | 連携用 URL は一度きり・短時間(10 分)有効で、開くと Google ログインを経て、そのチャットユーザーと Google アカウントが紐づく |
| FR-LK-03 | 1 つのチャットユーザーは 1 つの Google アカウントにのみ紐づく。1 つの Google アカウントは複数のワークスペースのチャットユーザーと紐づけられる |
| FR-LK-04 | `/asobell unlink` または WebConsole から連携を解除できる |
| FR-LK-05 | 連携 URL からの初回ログインは、許可リストの設定に関係なくアカウント作成を許可する(Bot が導入されたワークスペースのメンバーであることを認可根拠とする) |

### 3.4 WebConsole (FR-WC)

| ID | 要件 |
| --- | --- |
| FR-WC-01 | Google アカウントでログインできる。連携済みユーザー、または許可リスト(任意設定)に含まれるアカウントのみ利用可能 |
| FR-WC-02 | 対になる Provider の状態(種別、接続状態、担当ワークスペース)を閲覧できる(資格情報の登録・編集は WebConsole では行わない) |
| FR-WC-03 | ワークスペース設定(募集チャンネル、タイムゾーン、既定のリマインドポリシー等)を編集できる |
| FR-WC-04 | イベントを一覧・詳細表示・作成・編集・終了・中止できる。WebConsole から作成したイベントも、チャットから作成した場合と同じ管理(チャンネル作成、告知、ピン留め、リマインド、アーカイブ)を受ける |
| FR-WC-05 | WebConsole からイベントを作成する際の主催者は、ログインユーザーがそのワークスペースで連携済みのチャットユーザーとする |
| FR-WC-06 | 参加者一覧を閲覧し、参加者を除外できる |
| FR-WC-07 | リマインドの予定と送信履歴を閲覧し、即時送信できる |
| FR-WC-08 | 自分の連携済みチャット ID を一覧・解除できる |

### 3.5 Manager API (FR-API)

| ID | 要件 |
| --- | --- |
| FR-API-01 | イベントのライフサイクル操作を、gRPC サービスとして定義し grpc-gateway で導出した REST API で提供する |
| FR-API-02 | フロントエンド向けを含むすべての API は Protocol Buffers で定義する。OpenAPI 文書と TypeScript 型は proto から生成し、手書きしない |
| FR-API-03 | 認証は Manager の責務。Google ログイン、セッションの発行・検証・失効を Manager が行い、フロントエンドは Manager が発行した Cookie を保持するだけで認証ロジックを持たない |

### 3.6 サービス間通信 (FR-RPC)

| ID | 要件 |
| --- | --- |
| FR-RPC-01 | Manager と Provider は別コンテナで稼働し、gRPC で通信する |
| FR-RPC-02 | 1 つの Manager は 1 つの Provider にのみ接続する。1 つの Provider は 1 つのチャットツール接続(1 Slack App または 1 Discord Bot)のみを扱う。資格情報は Provider の環境変数またはコマンドライン引数で指定する |
| FR-RPC-03 | Manager と Provider は互いのアドレスを環境変数で静的に設定する。Manager は起動時に Provider の種別を確認し、DB に記録された種別と異なれば起動を中止する |
| FR-RPC-04 | gRPC の契約は Protocol Buffers で定義し、双方のコードを生成する |
| FR-RPC-05 | サービス間は共有トークンで認証する。TLS はリバースプロキシまたは設定で有効化できる |

## 4. 非機能要件 (NFR)

| ID | 要件 |
| --- | --- |
| NFR-01 | Slack / Discord のインタラクション応答期限(3 秒)を守る。重い処理は先に ACK してから非同期で行う |
| NFR-02 | ボタン連打・同時押下に対して参加者登録は冪等である |
| NFR-03 | プロセス再起動後もリマインドやチラ見の期限処理が失われない(ジョブは DB に永続化する) |
| NFR-04 | チャットツールの資格情報は DB に保存しない(Provider プロセスの環境変数のみ) |
| NFR-05 | Manager 1 コンテナ + Provider 1 コンテナ + MongoDB で動作する。Manager の水平スケールは v1 の範囲外だが、ジョブ処理は複数プロセスで衝突しない設計とする |
| NFR-09 | Provider が停止していても Manager は起動・応答し、該当 Provider を要する操作は明確なエラー(`provider_unavailable`)を返す。Provider 復帰後、未送信のリマインド等のジョブは再実行される |
| NFR-06 | 全時刻は UTC で保存し、表示時にワークスペースのタイムゾーンへ変換する |
| NFR-07 | 構造化ログ(JSON)を出力する |
| NFR-08 | 利用するライブラリは MIT / Apache-2.0 を原則とし、コピーレフトライセンスを採用しない |

## 5. スコープ外 (v1)

- 参加人数の上限管理、キャンセル待ち
- 出欠確認(投票)、日程調整
- WebConsole の権限管理(ロール)
- Slack の複数ワークスペースへの OAuth 配布(v1 は Provider ごとに手動トークン設定)
- 1 Manager への複数 Provider 接続、および Provider の自動発見。グループごとに Manager + Provider のペアを用意する
- 1 グループでの Slack と Discord の併用
- Discord の DM によるリマインド
- 多言語対応(v1 は日本語固定、文言は一箇所に集約し将来の差し替えを可能にする)

## 6. 主要ユースケース

### UC-01 イベントを立ち上げる

1. 主催者が任意の(公開)チャンネルで `/asobell new` を実行する
2. Bot が入力(タイトル・日時・説明・リマインドペース)を受け取る(Slack: モーダル、Discord: コマンドオプション)
3. Bot がイベントチャンネルを作成し、主催者を追加する
4. Bot が立ち上げメッセージをコマンド実行チャンネルへ投稿してピン留めし、募集チャンネルが設定されていれば同内容を投稿する
5. Bot がイベントチャンネルへ概要メッセージを投稿してピン留めする
6. リマインドポリシーに従ってリマインドジョブが登録される

### UC-02 参加する / チラ見する

1. ユーザーが立ち上げメッセージ(または募集チャンネルの告知・リマインド)の「参加」または「チラ見」を押す
2. Bot が参加者レコードを登録し、イベントチャンネルへユーザーを追加する
3. イベントチャンネルへ「@user が参加しました」/「@user がチラ見中です(1 時間)」を投稿する
4. チラ見の場合、1 時間後に除外するジョブが登録される
5. 立ち上げメッセージの参加者数表示が更新される

### UC-03 リマインドが届く

1. ジョブワーカーが期限到来のリマインドジョブを取得する
2. イベントチャンネルへ参加者メンション付きリマインドを投稿する
3. 募集チャンネルが設定されていれば、「参加」「チラ見」ボタン付きのリマインドを投稿する

### UC-04 チャットアカウントを連携する

1. ユーザーが任意のチャンネルで `/asobell login` を実行する
2. Bot が一度きりの連携 URL をエフェメラル(非対応なら DM)で返す
3. ユーザーが URL をブラウザで開く。未ログインなら Google ログインへ誘導される
4. 連携ページで「連携する」を押すと、チャットユーザーと Google アカウントが紐づく
5. 以後、WebConsole の「自分のイベント」や、WebConsole からのイベント作成で主催者として使われる

### UC-05 WebConsole からイベントを作成する

1. ユーザーが WebConsole でワークスペースと投稿先チャンネルを選び、内容を入力する
2. Manager が、ログインユーザーのそのワークスペースでの ChatIdentity を主催者として UC-01 の 3〜6 と同じ処理を行う
3. 主催者はイベントチャンネルに追加され、チャットで作成した場合と同様にコマンドで管理できる

### UC-06 イベントを終了する

1. 主催者がイベントチャンネルで `/asobell end` を実行する、WebConsole で終了操作をする、または終了予定時刻を過ぎる
2. イベント状態が `ended` になり、未送信のリマインドジョブが取り消される
3. 立ち上げメッセージのピン留めを解除し、ボタンを無効化した内容へ更新する
4. イベントチャンネルへ終了メッセージを投稿し、アーカイブ処理(Slack: archive、Discord: rename)を行う
